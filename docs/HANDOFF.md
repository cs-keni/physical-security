## Key architectural decisions

| Decision | Rationale |
|---|---|
| **Solutions isolated in `_solutions/` / `_answer_keys/`** | The learner explicitly asked not to be able to spoil exercises by scrolling. Never inline an answer. |
| **No placeholder files** | "Does the file exist?" must be a reliable completeness signal. Unwritten = empty dir + a `COURSE_PROGRESS.md` row. |
| **Calculators are stdlib-only** | Must run on a locked-down work laptop with no software request. |
| **Tests encode the hand calculations** | `32_Engineering_Math/` lessons are written *from* the test file. If a test fails after a formula change, redo the hand calc — don't change the test. Vindicated in Session 4: hand-checking units found two real `psec` defects the passing suite had missed. |
| **Device data model is the single source of truth** | Drawings, schedules, IP plan, cable schedule, commissioning tracker are all projections. This is the learner's differentiator. |
| **Validator reports, never mutates** | "Automate the repetitive work, never the engineering judgment." A tool that silently fixes data will silently break it. |
| **Phase-aware validation** | A validator that cries wolf gets ignored, which is worse than none. |
| **Bluebeam automation via exports, not scripting** | Scripting is Max-only; the user has Complete. Verified against official docs. |
| **Doors/hardware and electrical split into their own modules (35, 34)** | They're the top two junior knowledge gaps and deserve dedicated depth. |
| **Engineering math (32) separate from calculators (28)** | Derivations are pedagogically distinct from tools; separation prevents using a calculator you don't understand. |
| **`_solutions/` written in the same commit as the lessons that link to them** | Module 01 shipped lessons whose exercise links dangle, and that debt is still open. Modules 35 and 32 do not repeat it. Adopt this for every module from here on. |
| **Every numeric value in a code-backed module is produced by running the code** | Adopted in module 35, made a hard rule in module 32. Never hand-write a number into a lesson whose subject `psec` implements. It keeps prose and tests from drifting and it is what surfaced the two defects below. |
| **Worked numeric examples are computed with `psec`, not written by hand into prose** | Module 35 lessons 03 and 06 and their solutions were generated by running `psec.power` and transcribing the output. The numbers are reproducible and a formula change will surface as a mismatch rather than as stale prose. |
| **A complete module has a fixed shape** | Overview · lessons · `_solutions/` for every lesson · a capstone field exercise with a reference set · a quiz with an isolated answer key · a validated flashcard deck. **Module 35 is the reference implementation.** Match it. |
| **Worked examples chain across lessons within a module** | Module 35 lesson 06's voltage-drop example is deliberately the same opening as lesson 03's, and the answer changes once the transfer segment is added. Continuity teaches better than a fresh contrived example, and it makes the omission memorable. |

**Link check** — run after adding any module, since cross-references between modules are easy to
get wrong and nothing else catches them:

```bash
python3 - <<'EOF'
import re, os
root = os.getcwd()
pat = re.compile(r'\[[^\]]*\]\(([^)\s#]+)')
broken = []
for d, _, fs in os.walk(root):
    if '.git' in d:
        continue
    for f in fs:
        if not f.endswith('.md'):
            continue
        p = os.path.join(d, f)
        for m in pat.finditer(open(p, encoding='utf-8').read()):
            link = m.group(1)
            if link.startswith(('http', 'mailto')):
                continue
            t = os.path.normpath(os.path.join(d, link))
            if not os.path.exists(t):
                broken.append((os.path.relpath(p, root), link))
print(f"{len(broken)} broken links")
for f, l in broken:
    print(f"  {f} -> {l}")
EOF
```

Note: this reports every unwritten module referenced by a cross-link. Treat hits in *written*
modules as errors; hits pointing at directories listed as pending in `COURSE_PROGRESS.md` are
expected.

## Session 4 carry-overs

**Two `psec` defects found and fixed while writing module 32.** Test count **66 → 68**. Both were
found by working units by hand, not by the test suite.

1. **`video.stream_gb_per_day(decimal_gb=False)` divided decimal megabytes by 1024.** A bitrate is
   decimal, so those megabytes are 10⁶ bytes; converting to GiB divides by 2³⁰/10⁶ = 1073.741824.
   The bug reported the decimal/binary gap at TB scale as 4.86% against a true 9.95% — the exact
   error the function's own docstring warned about. It survived because the only test on that path
   asserted `binary < decimal`, which holds either way. Fixed with named constants
   (`MB_TO_GIB_BINARY` and siblings) plus `test_binary_units_are_true_gibibytes` and
   `test_decimal_binary_gap_at_tb_scale_is_about_ten_percent`, the latter asserting against
   `2**40/1e12` — a value from the definition rather than from a run.
2. **`pps.compare_interventions` docstring said "three levers" and returns four.** Fixed, with the
   module-32 cross-reference added.

**The generalisable lesson:** a green suite is not evidence the units are right. An assertion of
the form `a < b` passes for the wrong reason more often than it fails for the right one. Where a
figure has a *known* correct value derivable from a definition, assert against the definition.

**Module 32's lesson filenames are pinned by source.** `optics.py`, `video.py`, and `power.py`
docstrings name exact paths (`01_camera_fov.md`, `02_pixel_density.md`, `03_bandwidth.md`,
`04_storage.md`, `05_poe.md`, `06_voltage_drop.md`, `07_battery_ups.md`). Grep for
`32_Engineering_Math` across the repo before renaming anything in that directory.
