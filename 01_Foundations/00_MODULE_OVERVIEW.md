> you can use this vocabulary precisely and reason with these frameworks fluently. Do not
> rush it. If you only half-learn this module, everything after it will feel like memorization.

## Learning objectives for the module

By the end you can:

1. Explain the difference between security engineering and security management, and identify
   which questions belong to which discipline.
2. Use the risk vocabulary precisely enough that a risk analyst, an insurer, and a client
   executive would all agree you're using it correctly.
3. Decompose any protection problem into deter / detect / delay / assess / respond / recover
   and identify which function each proposed countermeasure actually performs.
4. Explain why "detect without assess" and "delay without response" are engineering failures,
   with examples.
5. Lay out concentric security zones for a facility and state the transition control at each
   boundary.
6. Apply CPTED principles and explain why they are usually the cheapest security available.
7. Convert a vague client statement into a set of testable, traceable requirements.
8. Trace any component through the full system it lives in, and enumerate its failure modes.
